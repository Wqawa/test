## Build.bat 编译失败（exit 1）排查

- 现象：`haxelib run lime build windows` 立刻崩，`Uncaught exception - load.c(357) : Primitive not found : lime@lime_audio_load(2)`，lime CLI 根本没跑到编译。
- 根因：vendored `.haxelib/lime/git` 是 CodenameCrew/cne-lime fork，仓库里提交的 neko CLI 字节码 `tools/tools.n`（2026-04-04 生成）早于 2026-07-26 的 `Squashed Audio Overhaul Changes`（8e081d7d，删掉了 `lime_audio_load` 这个原生 primitive）。本机按当前源码现编的 `lime.ndll` 没有该导出 → CLI 静态初始化即崩。
- 证据：旧 tools.n 里 `lime_audio_load` 出现 2 次，重编后 0 次；lime.ndll 里有 `lime_font_load`、没有 `lime_audio_load`；`neko run.n --version` 可复现。
- 修复：`cd .haxelib/lime/git/tools && haxe tools.hxml`（HAXELIB_PATH 指向仓库 .haxelib）。run.n 重编后字节一致，无需处理。
- 注意：`.haxelib/` 被 .gitignore 排除，且本工作区**没有 .git**（是 zip 解压的），所以修复只在本机；重新 clone/setup 库后问题会回来 → 可在 `building/lazy-build.ps1` 加一步"CLI 探测失败就重编 tools.n"自愈。
- 次生问题（本会话环境造成，非仓库问题）：hxcpp 建 PCH 报 `crtdbg.h` 找不到。原因是 VS/SDK 探测要调 reg.exe，被本会话沙箱拦了，INCLUDE 缺 ucrt 路径；手动补 `INCLUDE/LIB`（ucrt/um/shared/winrt + SDK Lib x64）后 PCH 正常，C++ 一路编到 48% 无 error。用户自己跑 Build.bat 环境正常。**另需把 `C:\Program Files (x86)\Windows Kits\10\bin\10.0.26100.0\x64` 加进 PATH，否则最后一步资源编译报 `Process creation failure : rc.exe`。**

## 推到 GitHub

- 工作区原本**没有 .git**（zip 解压）。远端确认：`https://github.com/Wqawa/Codename-Engine-Re-Encryption`（public，fork of CodenameCrew/CodenameEngine，默认 main）。
- 就地接管：`git init -b main` → `git fetch --depth=1 --filter=blob:none origin main` → `update-ref refs/heads/main FETCH_HEAD` → `git read-tree HEAD`（不动工作区）→ 只 add 我改的 6 个文件 → commit `8a229bc` → push 成功（9d221d6..8a229bc）。
- **踩坑**：这台机器的 HTTPS 被 SteamTools（Watt Toolkit）中间人代理，schannel 报 `CRYPT_E_NO_REVOCATION_CHECK`，openssl 后端缺 CA。解决：从 Windows 根存储导出 SteamTools 证书到 `C:\Users\S062PT\.git-ca-steamtools.pem`，本仓库设 `http.sslBackend=openssl` + `http.sslCAInfo` 指向它。
- `git reset`（mixed）在这个 blob:none 的浅克隆里会卡住/被杀，用 `git read-tree HEAD` 代替。
- 仓库现在是 shallow（depth=1），要全历史：`git fetch --unshallow`。
