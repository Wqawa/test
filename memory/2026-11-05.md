## 修：检查器工具窗口被主窗口盖住 + 调试界面的每帧开销（a850e4c7）

**现象**：① 在检查器里选中对象、用调整手柄（gizmo），手柄窗口会被游戏主窗口压在下面；
② 调试界面（ImGui 控制台/检查器）开着还是掉帧。

**置顶的根因**：ImGui 多视口模式下，一个窗口只要不完全落在游戏视口内就变成独立的系统窗口
（gizmo 跟着对象走到窗口边缘时就是这样）。这种普通顶层窗口一旦点回游戏就被压下去。
- lime 用的是 **SDL3 后端**：`ImGui_ImplSDL3_CreateWindow` 只在**创建窗口**时把
  `ImGuiViewportFlags_TopMost` 翻译成 `SDL_WINDOW_ALWAYS_ON_TOP`；`ImGui_ImplSDL3_UpdateWindow`
  **只有父窗口逻辑**，完全不处理 topmost（imgui_impl_win32.cpp 才有动态 SetWindowPos 的逻辑，
  别照着它写）。
- ImGui 每帧在 `AddUpdateViewport` 里用窗口自身的标志**重写** `viewport->Flags`（只保留
  IsMinimized/IsFocused），所以设一次会被下一帧抹掉。
- 结论：必须在 `begin()` 之后**每帧**补 `TopMost`，而且要在同一帧的系统窗口创建之前。
- 实现：`ImGuiUtil.pinCurrentWindowOnTop()`；调用点=Inspector、Object Properties、2dGizmo、3dGizmo、
  Console / Console Settings / Style Editor。合并进主视口时（id 等于 mainViewport）自动跳过。

**性能的根因**：`ConsoleInspector.updateObjects()` 每帧遍历每个状态和每个成员表来发现增删的对象；
运行中的 PlayState 有几百个成员，而相邻两帧几乎不变。而且面板收起到标题栏时也在跑。
- 改成 10 Hz 重建（`refreshInterval`），展开的组用同一个预算（`treeRefreshed` 门控
  `updateObjectMembers(member, true)`）；
- 重建挪进 `if (ImGui.begin("Inspector"))` 里：收起的面板不画行，也就没什么可重建。
- 控制台：`calcTextSize("Settings"/"Copy Log")` 每帧量字体 → 按 `style.fontScaleDpi` 缓存；
  `displayInput` 里每帧的 `ImGui.setScrollHereY(1.0)` 删掉（它同时是"控制台滚不上去"的原因），
  打开控制台时 `autoScrollNextFrame = true` 补一次。

**没做**：多视口本身每个次级窗口一次 MakeCurrent+Swap 的固定开销（SDL 后端 swapInterval=0，
不是 vsync 卡住），要彻底去掉只能关 `imguiMultiViewport`，代价是不能把面板拖到游戏窗口外。

构建 07:09:10，无 error。待用户验证：手柄拖到窗口边缘仍压在上面；检查器开着时的帧数。

## 修：关游戏时检查器崩 Null Object Reference（b8a64cac）

现场（用户截图）：`FlxObject.getScreenPosition():1135` ← `InspectorGizmo.show():95` ←
`ConsoleInspector.displayUI():234`，发生在试玩结束/关窗口时。

根因：`getScreenPosition` 里 `result.subtract(camera.scroll.x, ...)` 的 `camera` 是 null。
`prepareObjectCamera` 拿的是 `basic.getDefaultCamera()`，对象没有 camerase 时它落到 `FlxG.camera`；
状态切换（试玩回编辑器、关窗口进清理屏）会把相机全部拆掉，那一刻 `FlxG.camera == null`。

**是我上一条改动把它变容易碰到的**：树改成 10 Hz 重建后，选中的对象在状态切换后最多还能存活 100ms
（以前每帧重建，切换那一帧就查不到、selection 当场清掉），这段时间里 gizmo 就去投影一个死状态的对象。

修法：`InspectorGizmo.show` 在 `prepareObjectCamera` 之后 `camera == null` 直接 return（3D 版本来就
有这个守卫，2D 版漏了）；`ConsoleInspector.displayUI` 在 `FlxG.state` 变化时清空选中并当帧强制重建
（`__sinceRefresh = refreshInterval`），`FlxG.state == null` 时整个 displayUI 直接返回。

教训：**节流任何"用来判断对象还活着"的重建，都要顺手加一条"对象还有效吗"的直接检查**；
调试工具的一个 NPE 会把整个游戏拖进崩溃屏。

## 查：改过的官方 API 兼容性（3a6eaff8）

方法：拿 `baseline/upstream-1.1.0` 对 HEAD 做 diff，只扫 67 个 M 状态官方文件里的
`public (static) (function|var)` 行，找出「符号被删」和「同名函数签名变了」两类。
结果：删了 2 个公开符号、5 处签名变化，其中**只有 3 处会真的弄坏旧写法**：

1. `UIWarningSubstate` 第 4 参 `?isError:Bool` → `?kind:UIWarningKind`。老写法
   `(t, m, b, true)` 会类型不符。**改法**：第 4 参收 `Dynamic`，`Std.isOfType(kind, Bool)`
   时 true→ERROR / false→WARNING（正好对应旧版的 normal/grayscale 皮肤 + error/warning 图标
   + 红/黄染色）；另补 `isError(get, set)` 属性映射到 `kind`，脚本事后改它也有用。
   第 5 参仍是 `wantsInput`，`lines` 在第 6 位，旧调用不受影响。
2. `SaveWarning.warningFunc` 被删（我上一轮删的）。**改法**：字段恢复但**不调用**——
   删掉它只是为了让脚本赋值不报「字段不存在」，不调用才是不再双弹窗的原因。保存钩子仍是 `saveFunc`。
3. `Flags.SHADERS_CACHE_RESET_ON_SWITCH_STATE` 被删（迁移时丢的），连带 `GlobalScript.preStateSwitch`
   里的 `Main.refreshShaders()` 也没了。未知 flag 不会崩（`FlagMacro` 生成的 `parse` 兜底 return false，
   落到 `customFlags`），只是**静默失效**。**改法**：flag + 那一行调用一起恢复（默认 false）。

没恢复：`PlaytestingWarningSubstate`（内部弹窗，树里无引用，AGENTS 有恢复命令）。

顺便记：签名对比脚本的写法——按 `public function` 行取名字和参数串，同名但参数串不同即“签名变化”。
多行签名的会被误报成 `(field)`，要看一眼原文。
另外几处**签名没变但行为变了**的：`Chart.save` 打包 mod 直接写暂存目录；
`CoolUtil.safeSaveFile` 失败信息带路径并多写 `.cne/logs/save-errors.log`；
`SaveWarning.triggerWarning` 不再限 UIState；`MusicBeatState.add` 非 FlxBasic 返回 null；
`Flags.VOCAL_OFFSET_VIOLATION_THRESHOLD` 默认 25→12（迁移带过来的）。

## 修：密码 zip 里混明文条目（86a47e04）— 来自 D:/FNF/test/tools/out/REPORT.md

评估结论：CNEZ 容器没破（ChaCha20 + HMAC，220 次口令全失败），破的是同一批产物里的
`2hotBFmix_password.zip`——187 条 AES + **1 条明文** `songs/2hot-(bf-mix)/scripts/botplay.hx`
（`flags=0x0000`，普通 deflate）。`zipfile.read()` 直接读走。根因形状：有个写入器在包封好之后
**追加**条目，只搬字节、不加密（旧版的 `ZipInject`，现在源码里已没有，只在 `.workbuddy/bench/` 留了测试）。

修法（写入端证明 + 读取端点名）：
- `ZipAes.plaintextEntries(path)`：读中央目录，返回所有"有数据但没带 0x1 标志"的条目名。
- `ZipAes.encryptZip()` 写完、rename 之后自己重读一遍；有明文条目就删产物并抛异常
  （加密工具会把它显示成任务失败）。导出是唯一"决定一个包算封好"的地方，现在它自证。
- `ZipPassword.isProtected()` 原来遇到第一条加密条目就 return；改成计数，加密和明文都有时
  用 `Logs.warn` 点名警告（`mixedWarned` 保证一次运行只警告一次）。这条能覆盖**已经生成**的包。
- 实证：用同一套规则扫 `export/release/windows/bin/mods/2hotBFmix_password.zip` →
  228 条目，187 加密 / 1 明文，名字与报告一致。

**没修（报告里还开着的口子）**：
- V3 发布目录里源包 `2hotBFmix.zip` 和 `_password.zip` / `_encrypted.zip` 放一起；
- V4 解密后的视频落盘 `.cne/mods/<mod>/videos/`，只在正常退出时清；
- V5 内置兜底口令 `CNE::script::v1::d0nt_t0uch_th3_sky` 硬编码在 exe 里；
- V6 KDF 是 2048 轮裸 SHA-256（报告估算 ~500 万次/秒，弱口令几小时）。

**注意**：已经发出去的那个 `_password.zip` 仍然带着洞；新代码只会在日志里警告。
要真正封住必须用新版本重新导出（`encryptZip` 会把每个条目重新加密），或者把包删掉重发。

## 修：V5 内置口令 / V6 KDF（80d406af）

**V5（内置口令只能读）**
- `ScriptCrypto.isBuiltInKey()` / `warnBuiltInKey()`：读到用 `DEFAULT_PASSWORD` 封的包，日志点名
  警告一次（每包一次运行一次）。
- 封包拒绝：`EncryptionEditor.sealProblem()` 拦单包导出 / 批量队列 / 带 key 的脚本保护；
  `CnezV2.pack`、`ZipAes.encryptZip` 兜底抛错。唯一例外 `ZipEditCache.swapPackFile` 传
  `allowBuiltInKey = true`（按原密钥重封，否则老包改动后合并不回去）。
- 编辑器 Key 字段改成 `defaultKeyField()`：没有真 key 就空着，不再预填内置口令。

**V6（KDF）**
- `Pbkdf2.deriveSHA256`：ipad/opad 只算一次。**第一版漏了 U1 的外层 hash**，RFC 7914 向量
  （password/salt, c=1/2/4096, dkLen=32/40）一条都对不上，靠向量才发现；修完后四条全过。
- 实测（hxcpp，`haxe -cpp` 用仓库 `.haxelib` 编译小基准）：**6.35 ms / 1000 轮**，即 6.3 µs/轮，
  20 万轮 ≈ 1.3 s（neko 是 0.94 s/千轮，差 150 倍，别拿 neko 估）。
- CNEZ 容器 `VERSION` 2→3，`VERSION_MIN=2`；`HeaderV2` 带 `version`，`kdfFor(2)=1`、`kdfFor(3)=2`，
  `buildHeader(version, ...)` 用解析出来的版本重算根 tag（v2 包必须原样通过）。
- 脚本容器 `ScriptContainer.VERSION` 2→3，同样按版本选 KDF。
- 代价：解锁多 ~1.3 s（一次性，在加载屏出现之后）；攻击者每次尝试贵约 100 倍。

**兼容性**：v2 包/v2 脚本容器照常打开（走原来的 2048 轮代码）；**新包是 v3，旧版 exe 打不开**。
已发布且用内置口令封的包仍然是敞开的，只能重新封。
