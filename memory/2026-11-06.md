**背景图的生成方式（重要，下次加图标照抄）**

`default.png` 的排布我量过：408×389、黑底、描边 38 灰；16 个槽位，4 种朝向各 4 个，位置手摆

（`(cx, cy, rot)` 16 条，rot 是逆时针角度 0/90/180/270），只换字形：

- 图标先 `mask = px > 8` → 取 bbox → LANCZOS 缩到 66px → 乘 `38/255` 还原成 38 灰；
- 每个槽位 `rotate(-rot, expand=True)` 居中贴到槽位中心，叠加用 `ImageChops.lighter`（黑底=叠加）；
- 圆环从 `default.png` 自己抠一个、缩到 31px，按原位置贴。

生成脚本临时放在 `%TEMP%/bggen/gen.py`（没进仓库）。图标本体（`*_icon.png`）留在了 assets 里，
会进完整性清单和发布包（各 ~70KB），要不要挪到 `art/` 由用户定。

**代码**

  （`rotation = -5` 用的是 **FlxBackdrop 自己的 rotation 属性**，不是 `angle`；`velocity.set(85,0).degrees = rotation`）。
- **分层顺序容易错**：背景要画在遮罩**之上**。图本身已经是 15% 灰，压到 70% 遮罩（0xB4）下面只剩 4%，

  自检屏 5px（计数窗仍 `setSideOffset(sin(bobTime*1.5 + 2.1) * 5)` 用同一时钟错开），
  密码框 1px（输入框是焦点，大了光标会飘），解密屏 2px，其余 0。

## 合上游：afe74668 → 450ab5b5（ebc621ce）

上游 35 个提交 / 47 个文件。**本仓库和上游没有共同祖先**（基线 112aa91 是文件快照），2026-10-31
那次是 vendor 提交 `99c24d9d`（树 = afe74668 的树）加 `130391f4` 合并进来的，所以
`git merge-base HEAD upstream/main` 原本是空的。

**做法（可复用）**：
```
git remote add upstream https://github.com/CodenameCrew/CodenameEngine
git fetch upstream --filter=blob:none --no-tags
git replace --graft 99c24d9d afe74668     # 临时给它一个上游爹，merge-base 就有了
git merge --no-commit --no-ff upstream/main
# 解冲突 → git replace -d <sha> → git reset --soft HEAD → 普通提交
```

**关键教训：不要把上游提交真的接进历史**。合并提交会让上游 3587 个提交变成祖先，push 要把它们
的对象全部上传（本仓库 blob:none，本地压根没有那些 blob，`git rev-list --objects` 会触发
边拉边算、直接跑到超时）。改成 `git reset --soft` 压成普通提交后 push 只用了 5 秒。
所以 origin 里永远保持单线，AGENTS.md 开头写了以后怎么合。

**冲突 3 处**（都以官方为准，只保留必须的注入）：
1. `README.md`：收官方的 4 条 credits（FlxAnimate→flixel-animate 换仓库），留本 fork 自己那段。
2. `MainState.hx`：官方把"隐藏 ./.temp"包进 try/catch；本 fork 那个目录是 `.cne/temp`，
   `RuntimeDirs.ensure()` 已经建目录+隐藏+吞异常 → 留本 fork 那行。
3. `WindowUtils.hx`：收官方恢复的 `endfix`/`winTitle` 兼容属性；`updateTitle` 留本 fork 的空窗口
   守卫（所以不是 `inline`）。
